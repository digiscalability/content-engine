# P1.7 Metrics Pull and Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** `ce reconcile` follows every drafted post through Postiz to `scheduled`, `uploaded_private`, `published`, `rejected` or `failed` (§10). `ce metrics` stores a snapshot at 24 h, 72 h and 7 d after publish from `postiz analytics:post`, and resolves `{"missing": true}` through `posts:missing` / `posts:connect` (FR-LRN-1). `ce reject` records why Abbas deleted a draft.

**Architecture:**
- `engine/publish/postiz.py` grows `release_id` on `RemotePost` and a `PostizAnalytics` protocol (`post_analytics`, `missing_content`, `connect`) on both `PostizCLI` and `FakePostiz`.
- `engine/publish/youtube.py`: `Visibility` (`is_public(video_id)`) by YouTube's key-free oEmbed endpoint, plus a fake. It moves a private-route YouTube post from `uploaded_private` to `published` (the choice ADR 0002 left to this slice).
- `engine/learn/reconcile.py` and `engine/learn/metrics.py` hold the plain-Python jobs; the CLI wires them to the real adapters.
- `ce daily --dry-run` now runs the whole loop on fakes: draft → fake Abbas schedules and publishes → reconcile → a 24 h snapshot.

**Tech Stack:** Python 3.11, sqlite3, httpx (MockTransport in tests), Typer, PowerShell wrappers.

**Spec:** `docs/SRD.md` FR-LRN-1, §10 (states, step 3 reconcile, `ce reject`), FR-PUB-3 (`uploaded_private → published`), §11 `metrics_snapshots`, §13 (every 6 h `ce metrics` and `ce reconcile`; 04:00 `ce daily` then `ce reconcile`), NFR-1, NFR-7, NFR-8, §5.2 (`--dry-run`), ADR 0002 decision 1.

## Global Constraints

- No real Postiz call this session (no `POSTIZ_API_KEY`). Every external call sits behind an interface with a fake; a real call carries the `live` marker.
- Postiz runs only through `engine/publish/postiz.py` (pinned `postiz@2.0.27`). New CLI calls: `analytics:post <id> -d <days>`, `posts:missing <id>`, `posts:connect <id> --release-id <rid>` (checked against `gitroomhq/postiz-agent` 2.0.27 and `postiz-app` at `23f29c4`).
- Postiz post analytics are `[{label, percentageChange, data: [{total, date}]}]`, one data point holding the lifetime total today (YouTube: Views, Likes, Comments, Favorites; TikTok: Views, Likes, Comments, Shares). Or `{"missing": true}`, or `[]` when nothing is available.
- Slots `24h`, `72h`, `7d` (the table's CHECK). Columns filled: views, likes, comments, shares. watch_time, followers_delta and clicks stay NULL (Postiz has no source for them).
- NFR-1: reruns change nothing; `(post_id, at)` is the key; reconcile writes only differences.
- The engine never deletes anything in Postiz or YouTube.

## Review Focus

1. Postiz leaves a post out of `posts:list` because its channel was disconnected → its posts must not all become `rejected`. Test: a channel with open posts and no posts at all in the list rejects nothing and warns (Task 3).
2. The PC was off for days → three slots due at once must not store three copies of the same numbers. Test: at age 8 d only `7d` is written, never `24h` or `72h` (Task 4).
3. A TikTok account with a video posted outside the engine → `posts:missing` must not connect the wrong video. Test: more free candidates than missing posts connects nothing and lists the post for Abbas (Task 4).
4. A published post later deleted in Postiz → it stays `published`. Test (Task 3).
5. Postiz fails mid-run (exit 1, bad key) → no partial state and no key in the message. Test: the list call raising leaves every row as it was (Task 3); the contract test already masks the key.

## Tasks

1. **Postiz adapter** (`engine/publish/postiz.py`, `tests/contract/test_postiz_contract.py`, `tests/unit/test_postiz_rules.py`).
   - `RemotePost.release_id: str | None = None` from `releaseId`; `MISSING = "missing"`.
   - `AnalyticsResult(missing: bool, totals: dict[str, int])` and `parse_analytics(data) -> AnalyticsResult`: lowercase label → int of the last data point's total; non-numeric totals skipped.
   - `MissingCandidate(release_id: str, url: str)`.
   - `PostizAnalytics` protocol: `post_analytics(post_id, days) -> AnalyticsResult`, `missing_content(post_id) -> list[MissingCandidate]`, `connect(post_id, release_id) -> None`.
   - `FakePostiz`: `analytics` per post, `candidates` per integration, `raw_analytics/raw_missing/raw_connect` shaped like the API (missing only when `releaseId == "missing"`), `publish(post_id, url, release_id=None)`, `publish_missing(post_id)`. `FakeCliRunner` plays the three new commands.
   - Contract tests on CLI and fake: list carries the release id; analytics totals; `{"missing": true}`; missing → connect → analytics works; argv is `analytics:post <id> -d 7`, `posts:connect <id> --release-id <rid>`.
2. **YouTube visibility** (`engine/publish/youtube.py`, `tests/contract/test_youtube_visibility.py`).
   - `GET https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<id>&format=json`: 200 → public; 401, 403, 404 → not public; anything else or a transport error → `VisibilityError`. The id must match `^[A-Za-z0-9_-]{11}$` before a URL is built.
   - `FakeVisibility(public: set[str])`. One `live` test (a long-public video is public).
3. **Reconcile** (`engine/learn/reconcile.py`, `tests/unit/test_reconcile.py`).
   - `reconcile(conn, publisher, visibility, now) -> ReconcileReport(changes: list[Change(post_id, before, after)], warnings: list[str])`.
   - Checked against Postiz: posts with a `postiz_id` in `drafted`, `scheduled`, `failed`; `published` with `platform_id` NULL or `missing`; `rejected` with no `reject_reason`, updated in the last 30 days (restored if they reappear). One `list_posts` call, window from the oldest such post's date minus 30 days to now plus 365 days.
   - States by `engine_state()`; private route = YouTube with `ai_disclosure`. Writes `scheduled_at` (publish date), `published_at` (publish date, non-private), `platform_id` (release id, `missing` kept as is), `reject_reason` = `Postiz: <error>` (300 chars) for `failed`. All in one transaction after the list is read.
   - Absent from the list: `drafted`, `scheduled`, `failed` → `rejected`; `published` unchanged; a channel with open posts but none in the list → nothing rejected, a warning.
   - Then each `uploaded_private` YouTube post with a `platform_id`: `is_public` → `published`, `published_at = now`; `VisibilityError` → warning.
   - `reject(conn, post_id, reason)`: from `drafted`, `scheduled`, `uploaded_private` or `rejected` → `rejected` with the reason; otherwise `ReconcileError` naming the state. `open_posts(conn, now)` lists what a run would check (dry run).
4. **Metrics** (`engine/learn/metrics.py`, `tests/unit/test_metrics.py`).
   - `due_slot(published_at, now) -> str | None`: the latest slot whose age has passed; None before 24 h or after 14 days (`PULL_UNTIL`).
   - `pull_metrics(conn, analytics, now) -> MetricsReport(taken: list[tuple[int, str]], connected: list[tuple[int, str]], unresolved: list[int], empty: list[int])`: for each `published` post with a `postiz_id` and `published_at`, when the due slot has no row, `post_analytics(postiz_id, days)` (1, 3, 7). A row needs at least one of views/likes/comments/shares; else `empty`, retried next run.
   - Missing: set `platform_id = 'missing'`, then `missing_content`; free = candidates not already some post's `platform_id`; open = that channel's published posts with `platform_id = 'missing'`, newest first. Connect newest-to-newest only when the counts are equal; set each `platform_id`; re-pull this post once. Otherwise `unresolved`.
   - `due_snapshots(conn, now)` for the dry run.
5. **CLI, wrappers, digest** (`engine/cli.py`, `scripts/run_metrics.ps1`, `scripts/run_daily.ps1`, `engine/ops/digest.py`, tests in `test_cli.py`, `test_job_scripts.py`, `test_digest.py`).
   - `ce reconcile`, `ce metrics`: without `POSTIZ_API_KEY` exit 2 naming G0.7; with it, `PostizCLI` + `OEmbedVisibility`; `PostizError` → exit 1. `--dry-run`: no calls and no writes; prints what a live run would check.
   - `ce reject <post_id> "<why>"`.
   - `run_daily.ps1`: daily, reconcile, digest (each runs; exit = first failure). `run_metrics.ps1`: reconcile then metrics; the existing `ContentEngine-Metrics` entry now registers (dry run).
   - Digest: "Posts to connect in Postiz" for `published` posts with `platform_id = 'missing'`; the Studio link never uses `missing`.
6. **Dry run** (`engine/agents/dryrun.py`, `tests/unit/test_dry_run_follow_up.py`, `tests/golden/test_daily_dry_run.py`).
   - `follow_up(ctx, publisher, now) -> FollowUp(states: dict[int, str], snapshots: list[tuple[int, str]])`: fake Abbas schedules and publishes each draft (YouTube id `dryrun` + 5-digit post id), the fake says it is public, `reconcile`, then `pull_metrics` at `published_at + 25 h`.
   - Golden: the post ends `published` with one `24h` snapshot.
7. **Record:** ADR 0021, CLAUDE.md commands, PROGRESS tick.
