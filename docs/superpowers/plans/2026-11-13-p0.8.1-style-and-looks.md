# P0.8.1 Style Analyser and Looks (non-live) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** Everything P0.8 needs that does not need Gate 0b. The style analyser and `ce refs analyze` work on any reference video. Looks are a versioned format that renders apply (grade LUT, caption style, pacing). `ce look propose` renders three sample posts with a scripted proposer, and `ce look approve` saves the chosen look. P0.8.2 (live) runs it all on Abbas's reference shorts with Claude as the proposer.

**Architecture:** `engine/style/` holds `measure.py` (pure measurements from ffmpeg output and numpy arrays), `ocr.py` (a `TextDetector` protocol; RapidOCR with bundled models, plus a fake), `profile.py` (one reference to `RefMetrics`, many to a `StyleProfile`, stored in `style_profiles`) and `look.py` (`LookConfig`, a LUT generated from grade numbers, caption style, load and save). `render_post` applies the plan's look when its file exists, else the default look, and the report names which. `engine/style/propose.py` has a `LookProposer` protocol and a `ScriptedProposer` (three variants of the profile), and renders samples through the dry-run machinery.

**Tech Stack:** ffmpeg (scene detection, ebur128, raw frames), numpy, rapidocr-onnxruntime 1.4.4 (no network at run time), HyperFrames captions.

**Spec:** `docs/SRD.md` §9.1, §9.2, C10, D7, D8, §7.1 (`captions`, `look`), §18.2 P0.8.

## Global Constraints

- The engine never downloads third-party videos (§9.1); references come only from `references/inbox/<identity>/`.
- Only numbers and the palette are stored; reference files are deleted after measurement (C10). `--keep` exists for tests and re-runs.
- A look change is a new version file, never an edit in place (§9.2).
- Music stays licensed-library only; a look names a music feel, not tracks.

## Tasks

1. `measure.py`: cut times from ffmpeg scene scores, shot statistics, palette (k-means, 5 swatches), brightness and saturation, tempo from an onset envelope, text statistics from detected boxes. Pure functions with unit tests.
2. `ocr.py` and `profile.py`: `measure_reference()`, `aggregate()`, `store_profile()`; `ce refs analyze <identity> [--keep]`.
3. `look.py`: `LookConfig` (grade, captions, title card style, pacing, music feel), `grade_lut()`, `caption_style()`, `find_look()`; `render_post` applies the look.
4. `propose.py`: `ScriptedProposer`, `render_samples()`; `ce look propose <identity>` and `ce look approve <identity> <n>`.
5. Golden: two generated reference clips with known cuts, colours and beat, measured by real ffmpeg and OCR; a profile; three sample renders that differ in grade; approval writes `looks/<identity>-v1.yaml` in a temporary config. ADR 0015.

## Review Focus

1. A reference file must not be deleted before its profile is stored → `test_refs_are_deleted_only_after_the_profile_is_stored`.
2. Approving must never overwrite an existing look version → `test_approve_writes_the_next_version`.
3. A plan whose look file is missing must still render, and say it used the default → `test_render_report_names_the_look`.
4. Measurements on a silent or text-free video must not crash → `test_measure_handles_silence_and_no_text`.
5. LUT values stay inside 0–1 for any grade the model allows → `test_grade_lut_stays_in_range`.
