> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** Everything the agents stand on, testable without calling Claude: submission schemas and the RunReport (§5.6), the read and submit tools (§5.4), hooks H1–H5 with deny tests (§5.5), agent definitions with prompt files (§5.3), the `ClaudeAgentOptions` builder for unattended runs (§5.6), and FR-AGT-1.

**Architecture:** `engine/agents/` — `schemas.py` (pydantic), `state.py` (config→DB identity mirror), `tools.py` (pure `ToolSpec` handlers on a `ToolContext`, wrapped as in-process MCP tools `mcp__engine__*`), `hooks.py` (pure decision functions plus async SDK callbacks registered with `on_failure="block"`), `definitions.py` (§5.3 table, prompts from `engine/prompts/*.md`), `options.py` (`build_options`, `agent_env`, `scrub_process_env`). Action tools (voice, avatar, render, draft) are P0.7b; QA checks are P0.7c.

**Tech Stack:** `claude-agent-sdk` 0.2.181 (Python): `ClaudeAgentOptions`, `tool`, `create_sdk_mcp_server`, `HookMatcher(matcher, hooks, on_failure)`, `AgentDefinition` (camelCase fields), `SystemPromptFile`; hook callbacks `(input_data, tool_use_id, context)` returning `{"hookSpecificOutput": {"hookEventName", "permissionDecision": "deny", "permissionDecisionReason"}}`.

**Spec:** `docs/SRD.md` §5.2–§5.6, §4.1, §8.2, §8.3, §17, FR-PLN-3, FR-PRD-1, FR-PRD-4, FR-SRC-2, FR-UND-4, FR-QA-7, FR-AGT-1, GR-6, GR-9, NFR-3.

## Findings (installed SDK source)

- The agent subprocess gets `{**os.environ, **options.env}`: a vendor key in the Windows environment would reach the agent, so `scrub_process_env()` removes vendor key names from `os.environ` before a run and `options.env` carries only `ANTHROPIC_API_KEY`.
- Agent definitions travel in the initialize request, not on the command line; the orchestrator prompt goes as `{"type": "file", "path": …}`.
- A tool reports failure with `"is_error": True`; MCP names are `mcp__<server key>__<tool>`; `allowed_tools` only pre-approves, so `dontAsk` plus `disallowed_tools` keep Bash and web tools out.

## Global Constraints

- Tools per agent exactly as §5.3; no Bash, WebSearch, WebFetch, Write, Edit for any agent (§5.4, GR-9); `Read` only under `config/`, `engine/prompts/`, `media/work/` (H2).
- `permission_mode="dontAsk"`, no `can_use_tool`, `setting_sources=["project"]`, `cwd` = repo root, `max_turns` per agent, `max_budget_usd` from `engine.yaml` (daily 3), `output_format` = RunReport JSON schema (§5.6).
- Format lengths (§4.1): A 30–75 s, B 20–60 s, C 30–60 s. Reading speed ≤ 3 words/s (FR-PRD-1). Tiers per format (§8.1): `film_reference` only in A.

## Review Focus

1. A brief without a difference note is rejected (FR-PLN-3 accept). → `test_submit_brief_rejects_a_missing_difference_note`.
2. `Read` of `config/../.env` or a path differing only in case must be denied. → `test_h2_denies_traversal_and_case_tricks`.
3. A crashing guard must block, not allow. → `test_hooks_register_with_on_failure_block`.
4. `search_library` must never return `film_reference` for B/C, people-unknown assets as B-roll, or expired licences. → `test_search_library_filters`.
5. A vendor key present in the process environment must not reach the agent. → `test_scrub_removes_vendor_keys_from_process_env`.
