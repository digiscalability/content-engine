# P0.6b.1 Own-Footage Library on Fixtures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Own footage enters the library from listed folders, is cut into scenes with keyframes, gets text and CLIP embeddings in sqlite-vec, passes the people rule, and `search_library` returns rights-clean, people-clean cutaway candidates for 5 sample beats, all on generated fixture footage.

**Architecture:** One migration adds the sqlite-vec tables, an own-footage index status table and the people-mark audit table. Pure understanding steps (scenes, keyframes, transcript chunks, keyframe embeddings, face check) move into one shared module used by the new `Ingester` and the existing `FilmIndexer`. Models sit behind protocols with fakes (NFR-8); the real CLIP and YuNet run on onnxruntime and OpenCV from a pinned Hugging Face cache. `search_library` filters by rights, people and licence first, then ranks by `vec_distance_cosine` in SQL.

**Tech Stack:** Python 3.11, sqlite3 + `sqlite-vec` 0.1.9, onnxruntime, tokenizers, OpenCV 5 (`cv2.FaceDetectorYN`), Pillow, ffmpeg 8, Typer, pytest.

**Spec:** `docs/SRD.md` FR-ING-1, FR-ING-4, FR-UND-2, FR-UND-3, FR-UND-5, FR-SRC-2, FR-SRC-3, §5.4 `search_library`, §8.1, §8.3, §11, §13, C12, C13, NFR-5, NFR-8, NFR-9; `docs/PROGRESS.md` P0.6b.1.

## Global Constraints

- Footage enters only through `config/sources.yaml`; no code path writes it (FR-SRC-3). Only folders Abbas names in chat go in (G0.9c).
- Fixtures are generated at test time; real footage never enters the repo (NFR-9).
- Model downloads (CLIP ViT-B/32 ONNX about 608 MB, YuNet 0.2 MB) only after Abbas's yes in chat.
- Own folders are indexed in place and read-only: nothing is written beside the footage, no raw copies.
- Vectors: text 384 floats (`bge-small-en-v1.5`), image 512 floats (CLIP ViT-B-32), per ADR 0006.
- `search_library` never returns `film_reference` for formats B or C (§5.4) and never an asset with `people_release` other than `none` or `yes` (§8.3).
- Ingest stops below `disk.stop_free_gb` (FR-ING-4, NFR-5).
- Applied migrations are never edited; schema changes are a new numbered file (ADR 0006).
- Conventional Commits on `feat/p0.6b.1-own-footage-library`, files staged by name.

## Review Focus

1. Abbas marks an asset `yes` or `exclude`, then ingest runs again: the mark must survive (a re-run never resets `people_release`). Test in Task 5.
2. Scenes or chunks rebuilt for an asset: the old vector rows must go with them, so no vector points at a deleted or reused scene id. Test in Task 3.
3. The same bytes under two paths, or one file seen twice: one asset, and an unchanged file is not hashed again on the next run. Test in Task 4.
4. A clip with no audio, or shorter than a second, or with no cuts: no transcript step failure, exactly one scene. Test in Task 3.
5. `search_library` with a query before anything is embedded, or without the embedders (read-only context): no crash; it falls back to the text match and says so. Test in Task 6.

### Task 2: Pinned models: CLIP and YuNet behind protocols, with fakes

**Files:**
- Create: `engine/library/models.py`, `engine/library/clip.py`, `engine/library/faces.py`
- Modify: `engine/library/embeddings.py` (use `PinnedModel`), `engine/doctor.py` (one check per model plus sqlite-vec), `engine/cli.py` (`ce models fetch` fetches every pinned model)
- Test: `tests/unit/test_clip.py`, `tests/unit/test_faces.py`, `tests/unit/test_doctor.py`, `tests/model/test_clip_model.py` (`-m model`)

**Interfaces:**
- `PinnedModel(repo: str, revision: str, files: tuple[str, ...], purpose: str)` with `.paths(cache_dir=None) -> dict[str, Path]` (raises `EmbeddingModelMissing`) and `.fetch(cache_dir=None) -> list[Path]`; `PINNED: dict[str, PinnedModel]` keys `bge`, `clip`, `yunet`.
- CLIP pin: `Xenova/clip-vit-base-patch32` @ `6b7c523703ae26e39be4b03774966f8571c7f523`, files `onnx/text_model.onnx`, `onnx/vision_model.onnx`, `tokenizer.json`. YuNet pin: `opencv/face_detection_yunet` @ `3cc26e7f1014a5ee5d74a42acee58bafc9d0a310`, file `face_detection_yunet_2023mar.onnx`.
- `ImageTextEmbedder` protocol: `name: str`, `embed_images(paths: Sequence[Path]) -> np.ndarray` (n×512, unit rows), `embed_texts(texts) -> np.ndarray` (n×512).
- `ClipOnnx(cache_dir=None)`; `clip_pixels(image: PIL.Image) -> np.ndarray` (1×3×224×224: shortest side to 224 bicubic, centre crop, /255, mean `0.48145466, 0.4578275, 0.40821073`, std `0.26862954, 0.26130258, 0.27577711`); text max 77 tokens.
- `FakeClip`: colour prototypes (orange, blue, black, green, white, red); an image is its share of pixels nearest each prototype; a text is the prototypes its words name (`sun, sunrise, dawn, morning, orange` → orange; `ocean, sea, wave, water, blue` → blue; `night, star, stars, moon, dark` → black; `forest, tree, trees, grass, field, green` → green; `notebook, page, paper, write, white` → white; `fire, red, heart` → red); vectors padded to 512 and normalised.
- `FaceDetector` protocol: `count(image_bgr: np.ndarray) -> int`. `YuNet(cache_dir=None, score=0.6)`. `FakeFaces`: counts blobs of pure magenta (255, 0, 255) pixels of at least 1% of the frame.

- [ ] Tests: `test_clip_pixels_shape_and_normalisation` (a grey 640×360 image gives mean ≈ (0.5−mean)/std per channel); `test_fake_clip_ranks_colour_words` (orange image ranks "sunrise" above "ocean"); `test_fake_faces_counts_magenta`; `test_doctor_reports_each_model` (bge, clip-vit-base-patch32, face_detection_yunet; warn when missing, naming `ce models fetch`); `test_doctor_reports_sqlite_vec`. Model tests (after download): real CLIP ranks the matching caption first for each drawn fixture still; YuNet finds no face in the five scene stills.
- [ ] Red, green, commit `feat(library): pinned CLIP and YuNet models with fakes (P0.6b.1)`.
