# P1.1 Job Wrappers, GPU Lock, Logs, Digest and Notification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** The operational shell around the engine (SRD §13):
- `scripts/run_<job>.ps1` wrappers that run `ce` without a console window, log one file per job per day and pass on the exit code;
- a GPU file lock that serialises renders and transcription;
- `ce digest`, which writes `reports/YYYY-MM-DD.md` from the database and shows a Windows notification that opens it whenever something waits on Abbas;
- `scripts/register-tasks.ps1`, a dry run by default, with registration only on Abbas's yes.

**Architecture:**
- **`engine/ops/gpu_lock.py`:** an OS file lock (`msvcrt` on Windows), released by the OS if the process dies; a busy lock waits up to a timeout.
- **`engine/ops/digest.py`:** builds the digest from `posts`, `qa_results`, `budget_ledger` and the day's run reports, and drops avatar requests and holds older than 48 h with a reason.
- **`engine/ops/notify.py`:** a `Notifier` protocol; `ToastNotifier` uses windows-toasts with a `file:///` launch action, so a click opens the digest after the engine has exited.
- **PowerShell:** `scripts/JobCommon.psm1` copies the ventures-ops conventions (§2.3): one log per job per day under `%LOCALAPPDATA%\content-engine\logs`, logs pruned after 30 days, native exit codes trusted over stderr.

**Tech Stack:** Python 3.11, msvcrt, windows-toasts 1.3.1, PowerShell 5.1, Task Scheduler (registration deferred).

**Spec:** `docs/SRD.md` §13, §2.3, D11, C17, NFR-1, NFR-6, NFR-7, FR-PRD-3, FR-PUB-3.

## Global Constraints

- No Task Scheduler job is registered in this slice: `register-tasks.ps1 -Apply` waits for Abbas's yes in chat.
- Tasks wake the computer and run as soon as possible after a missed start (§13).
- No secrets in logs or the digest (NFR-7): the wrappers log `ce` output only; the digest holds ids, titles and links.
- Digests are generated files: `reports/*.md` stays out of git.

## Tasks

1. GPU lock: `GpuLock`, `paths.gpu_lock`, `ToolContext.gpu_lock`; `render_post` and `ce refs analyze` take it. Tests include a second process holding the lock.
2. Digest: `expire_waiting()`, `build_digest()` (drafts to approve, holds with reasons, avatar request cards, YouTube label ticks, failures, budget, needs-Abbas links), `write_digest()`.
3. Notification and `ce digest [--date] [--no-notify]`; a summary line such as "3 drafts to approve, 1 avatar request".
4. PowerShell: `JobCommon.psm1`, `run_daily.ps1` (daily, then digest), `run_digest.ps1` (the morning repeat), `register-tasks.ps1`. Pytest drives them with a fake command and a temporary log folder.
5. ADR 0016; verify, including one real toast; record.

## Review Focus

1. A crashed job must not leave the GPU locked → `test_a_dead_holder_releases_the_lock`.
2. Two jobs must never hold the GPU together → `test_a_second_process_waits_then_times_out`.
3. A digest must be rebuildable the same day without duplicating or losing items → `test_digest_is_rebuilt_from_state`.
4. The wrapper's exit code must be `ce`'s → `test_wrapper_passes_on_the_exit_code`.
5. Nothing is registered without `-Apply` → `test_register_tasks_is_a_dry_run_by_default`.
