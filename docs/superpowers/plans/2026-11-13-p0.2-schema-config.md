# P0.2 Schema, Migrations and Config Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native (one slice per session, built in that session).

**Goal:** The SQLite schema of SRD §11 behind a versioned migration runner, pydantic models and a loader for `config/`, and FR-SRC-1 validation, so later slices store and read state through checked shapes.

**Architecture:** `engine/db/` holds `connect`/`migrate`/`open_db` and plain SQL migrations numbered `NNNN_name.sql`, tracked with `PRAGMA user_version`; constraints live in the SQL (NOT NULL, CHECK, UNIQUE, FK, one trigger) so a bad row fails at the database whatever code wrote it. `engine/config/` holds pydantic models (`extra="forbid"`) and `load_config`, which collects every problem across files into one `ConfigError`. `ce doctor` gains a config check.

**Tech Stack:** Python 3.11 `sqlite3` (SQLite 3.45.1, JSON built in), pydantic 2, PyYAML.

**Spec:** `docs/SRD.md` §11 (data model), §12 (config), §6.1 (FR-SRC), §8, §10, §17. Build rules: `docs/BUILD_PROMPT.md`.

**Requirement ids touched:** FR-SRC-1 (validation, DB NOT NULL), FR-SRC-2 (licence fields on sources and assets), FR-SRC-3 (no code path writes `sources.yaml`), GR-1 (DB NOT NULL and rights trigger), FR-ING-1 (sha256 UNIQUE, the dedupe basis), FR-ING-2 (config: `channel` sources only for `own`/`partner_written`), FR-UND-4 (moment scores and scorer version NOT NULL), FR-PLN-3 (brief difference note NOT NULL), FR-TRD-1 (trend source, query, date, score NOT NULL), FR-PUB-4 (`min_gap_hours >= 3`), GR-5 (format C channels require disclosure), §8.2 (film share ≤ 0.2; film only from drives), §8.3 (`people_release` defaults to `unknown`), §10 (post states), §17 (autonomy level 0 or 1), NFR-1 (unique keys that make retries idempotent: metrics per post and window, ledger `charge_key`, post per brief and channel), NFR-3 (`agent_runs`, `tool_calls`).

## Global Constraints

- SQLite at `data/engine.db`, "migrations versioned in `engine/db/migrations/`, foreign keys on, WAL mode" (§11).
- Rights tiers: `own`, `ai_generated`, `stock`, `partner_written`, `cc_by`, `public_domain`, `film_reference` (FR-SRC-1).
- Source kinds: `folder`, `drive`, `channel`, `library` (§11).
- Post states (§10): `planned`, `scripted`, `voiced`, `avatar_waiting`, `avatar_ready`, `rendered`, `qa_failed`, `qa_held`, `qa_passed`, `drafted`, `uploaded_private`, `scheduled`, `published`, `rejected`, `failed`.
- Metrics windows: `24h`, `72h`, `7d` (§11, FR-LRN-1). Formats: `A`, `B`, `C` (§4.1). Platforms: `youtube`, `tiktok`, `instagram`.
- Autonomy levels: 0 and 1 only (§17). Posts on one channel ≥ 3 h apart (FR-PUB-4). Film breakdown share ≤ 0.2 (§8.2).
- Engine effort values: `low`, `medium`, `high`, `xhigh`, `max`.
- No code path writes `sources.yaml` (FR-SRC-3). Config never holds secrets.
- sqlite-vec tables (`text_vec`, `image_vec`) arrive with the embeddings in P0.6b, where the extension and vector sizes are proven (ADR 0006).
- Branch `feat/p0.2-schema-config` cut from `main`; Conventional Commits; stage by name; `set -o pipefail` before chaining a commit onto a test run.

## Review Focus

1. A Windows path in double quotes (`path: "C:\Users\me\Pictures"`) is a YAML escape error; the loader names the file and says to use single quotes, never a raw traceback. → Task 3 `test_double_quoted_windows_path_gets_a_hint`.
2. A typo'd key (`rights_prof:`) is rejected, not silently ignored, so a source never loads without its proof. → Task 3 `test_unknown_key_rejected`.
3. A blank or comment-only `sources.yaml` (Abbas clears it) gives a clear error, not `NoneType` crashes. → Task 3 `test_blank_sources_file_is_an_error`.
4. A database written by a newer engine (higher `user_version`) is refused instead of half-migrated. → Task 1 `test_newer_db_than_code_refused`.
5. A failing migration leaves the database at the previous version with none of its tables. → Task 1 `test_failed_migration_rolls_back`.

### Task 1: migration runner

**Files:**
- Create: `engine/db/__init__.py`, `engine/db/migrations/` (empty in this task), `tests/unit/test_db_migrations.py`

**Interfaces:**
- Produces (`engine/db/__init__.py`):
  - `MIGRATIONS_DIR: Path` (`engine/db/migrations`)
  - `@dataclass(frozen=True) class Migration: version: int; name: str; sql: str`
  - `class MigrationError(Exception)`
  - `load_migrations(directory: Path = MIGRATIONS_DIR) -> list[Migration]` — files `^(\d{4})_([a-z0-9_]+)\.sql$`, sorted; versions must run 1, 2, 3… with no gap or duplicate (`MigrationError`).
  - `connect(path: Path | str) -> sqlite3.Connection` — `isolation_level=None`, `row_factory=sqlite3.Row`, `PRAGMA foreign_keys = ON`, `PRAGMA journal_mode = WAL`, `PRAGMA busy_timeout = 5000`.
  - `schema_version(conn) -> int` (`PRAGMA user_version`)
  - `migrate(conn, directory: Path = MIGRATIONS_DIR) -> list[int]` — refuses (`MigrationError`) when `schema_version` > latest file; applies each pending file as `BEGIN; <sql>; PRAGMA user_version = N; COMMIT;` via `executescript`, rolling back on error; returns applied versions.
  - `open_db(path: Path) -> sqlite3.Connection` — creates the parent folder, connects, migrates.
