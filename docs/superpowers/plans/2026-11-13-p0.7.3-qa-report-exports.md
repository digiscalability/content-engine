# P0.7.3 QA Checks, Render Report and Exports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** Deterministic QA checks FR-QA-1, 5, 6 and 8 (`run_qa_checks`), `render_report.json` (FR-PRD-7, `get_render_report`) and FCPXML + OTIO exports (C7, D12) for every render, so `ce daily --dry-run` goes brief → MP4 → QA → review → a fake Postiz draft.

**Architecture:** `engine/qa/` holds the checks as pure functions returning `CheckResult(name, result, reasons)`: rights (the existing `rights_violations`, moved here), disclosure, banned terms and claims about Abbas. `run_qa_checks` stores one `qa_results` row per check and moves the posts to `qa_failed` / `qa_held`; `submit_qa_review` runs only after every check passed and moves them to `qa_passed`, `qa_held` or `qa_failed`, once per render. `create_draft` re-runs the text checks on titles, captions and hashtags (FR-QA-8 covers them). `render_post` writes one folder per render: the MP4, `render_report.json`, `<name>.fcpxml` and `<name>.otio`.

**Tech Stack:** Python 3.11, SQLite, ffmpeg `ebur128`, `opentimelineio` 0.18 (OTIO), FCPXML 1.8 written with `xml.etree`; `otio-fcpx-xml-adapter` (dev only) reads the FCPXML back in tests.

**Spec:** `docs/SRD.md` FR-PRD-7, §6.7 (FR-QA-1, 5, 6, 7, 8), §7.4, §16, C7, D9, D12.

## Global Constraints

- The Public Fact Sheet is read at runtime from `qa.fact_sheet` in `engine.yaml`; it is never copied into the repo (NFR-9: it holds a phone number and an ABN).
- Hard fails stop the post (§6.7); a claim the engine cannot check is a hold, never a pass.
- The keyword screens are deterministic floors; the qa-reviewer judges meaning (FR-QA-7).
- Term lists live in the identity YAML as proposals Abbas confirms, like the playbook.

## Tasks

1. Config: `qa.fact_sheet` (engine) and `qa.banned_terms` / `qa.never_terms` (identity). `engine/qa/text.py`: `post_texts()`, `banned_terms_check()`, `claims_check()` with the SRD's acceptance pair ("when I worked at a restaurant in Sydney" fails; "a former chef" passes).
2. `engine/qa/rights.py` (moved `rights_violations`), `rights_check()`, `disclosure_check()`; `run_qa_checks` tool; `submit_qa_review` gated and moving posts; `create_draft` checks its copy.
3. `engine/produce/report.py`: `measure_loudness()`, `build_render_report()`; render folder layout; `get_render_report` tool.
4. `engine/produce/exports.py`: `plan_timeline()` (OTIO: V1 shots with time warps and freezes, V2 captions and overlays, A1 voice, A2 music, A3 SFX), `write_otio()`, `write_fcpxml()`.
5. Dry run: run QA, a scripted review, scripted copy, `create_draft` on FakePostiz; golden test extended (report, exports, QA rows, the draft).
6. ADR 0013; verify; tick P0.7.3 and P0.7.

## Review Focus

1. A render reviewed before its checks ran must not reach `qa_passed` → `test_review_needs_every_check_passed`.
2. A second review must not turn a hold into a pass → `test_a_render_is_reviewed_once`.
3. A title or hashtag that breaks FR-QA-8 must not reach Postiz → `test_create_draft_checks_the_copy`.
4. A self-reference with no Fact Sheet to check against must hold, not pass → `test_claims_without_a_fact_sheet_hold`.
5. Export timings must match the render frame for frame → `test_exports_match_the_plan_timing`.
