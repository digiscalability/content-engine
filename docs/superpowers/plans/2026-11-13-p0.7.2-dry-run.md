# P0.7.2 Action Tools and the Dry Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution for this slice is native.

**Goal:** The four action tools (`synthesize_voice`, `request_avatar`, `render_post`, `create_draft`) and `ce daily --dry-run`, which takes one post per due identity from brief to MP4 on fakes, through the same tools and guards the agents use.

**Architecture:** `ToolContext` gains `Providers` (voice, avatar, publisher, transcriber factory, overlay renderer, render settings, ffmpeg runner) and a media root. Generated files become assets of a built-in `engine` source (migration 0002: `ai_generated`, people `none`). Post rows (one per brief and channel, §10) are created with the brief and advanced by each tool. `hooks.guard_table()` is the one list of guards; `build_hooks()` (SDK) and `GuardedTools` (dry run) both read it. `engine/agents/dryrun.py` holds the scripted director: it plays orchestrator and scriptwriter with fixed, rule-abiding content and a generated cutaway library, in a throwaway DB and media folder under `media/dry-run/<run_id>/`, with fake ids filled into a copy of the config.

**Tech Stack:** Python 3.11, SQLite, ffmpeg (NVENC), HyperFrames 0.9.40 for captions, fakes from P0.6.

**Spec:** `docs/SRD.md` §5.2 (`--dry-run`), §5.4, §5.5, §10, FR-PRD-2, FR-PRD-3, FR-PRD-5, FR-PRD-6, FR-PUB-1–4, NFR-1, NFR-8.

**Flow (also the orchestrator prompt's, corrected):** brief → script → voice → avatar → edit plan (now that the VO and avatar assets exist) → render (mix, transcription of the mix, refined starts, HyperFrames captions, encode) → QA (P0.7.3) → draft. `create_draft` refuses a post that is not `qa_passed`, so this slice's dry run ends at the MP4.

## Global Constraints

- Every external call is faked in the dry run (NFR-8); HyperFrames and ffmpeg run for real (local tools).
- Dry-run state never touches `data/engine.db` (its own DB per run).
- A script is charged once (`voice:script:<id>`), an avatar job requested once (job file), NFR-1.
- Drafts only at L0 (GR-4): `create_draft` makes Postiz drafts; nothing schedules.
- Overlay blocks need a look (P0.8): until then a plan with overlays is refused; captions only.

## Tasks

1. Identity `voice_id` and `avatar_id` (empty until G0.4/G0.5); migration 0002 seeds the `engine` source; `register_generated()`; the id `engine` is reserved in `sources.yaml`.
2. `guard_table()` shared by `build_hooks()` and `GuardedTools`; `Audit.record()` used by both.
3. Post rows: `submit_brief` creates one `planned` row per channel (`ai_disclosure` 1 for format C or a `required` channel); `advance_posts()` moves them forward only.
4. Action tools on fakes: `synthesize_voice {script_id}`, `request_avatar {brief_id, script_id}`, `render_post {edit_plan_id}`, `create_draft {render_id, copy[]}`; `FakeAvatar` (an ffmpeg card video of the voice's length) and `ScriptAlignedTranscriber` (script words spread over the mix).
5. `dryrun.py`: `dry_run_config()`, fixture cutaway library, director, `daily_dry_run()` → `RunReport` (also `run_report.json`); `ce daily --dry-run`; live `ce daily` exits pointing at P0.9. Orchestrator and scriptwriter prompts follow the corrected flow.
6. `tests/golden/test_daily_dry_run.py`: brief, script and edit plan rows exist; the MP4 passes the FR-PRD-5 probe; a caption is on screen. ADR 0012; tick P0.7.2.

## Review Focus

1. A second dry run must not see the first run's posts or spend → each run gets its own DB (`test_each_dry_run_has_its_own_db`).
2. Rerunning `synthesize_voice` for the same script never charges twice → `test_synthesize_voice_twice_charges_once`.
3. An avatar that is waiting must not reach the edit plan → `test_request_avatar_waiting_returns_no_asset`.
4. Drafting an unchecked render must be refused → `test_create_draft_requires_qa_passed`.
5. Avatar shots stay lip-synced: their `in`/`out` equal timeline time → `test_director_plan_keeps_avatar_in_sync`.
